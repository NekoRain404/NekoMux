# NekoMux — project conventions

Working notes for anyone (human or agent) changing this codebase. Keep this file
short and about rules, not status.

## Hard rules

**No source file may exceed 800 lines.** This applies to every `.dart` file
under `lib/`. When a file approaches the limit, split it by responsibility
before adding to it — extract a service, a widget, or a set of pure helpers into
their own file. Do not split by copying a block out and leaving the rest behind;
move a coherent unit.

**Comments are written in English only.** This replaced the earlier bilingual
(English + Chinese) convention on 2026-09-16. Write new comments, doc comments
and TODOs in English; do not add a Chinese line. Existing bilingual comments are
left as they are — do not mass-convert them, and do not add Chinese to a comment
you are already editing.

**Run `flutter analyze` and `flutter test` before claiming a change works.** Both
must be clean. The project had zero tests until 2026-09-15; new logic that can be
tested in isolation should get a test.

**Never commit signing material.** `android/key.properties`, `android/*.jks` and
`android/*.keystore` are gitignored. They are the release key — losing it means
future APKs cannot update installed releases. Before any `git add -A`, confirm
with `git status --ignored` that they are still ignored.

## Size

**Every file under `lib/` is currently under the 800-line limit.** Keep it that
way — when a file approaches it, move a coherent unit out before adding more
(an extracted service, widget, or set of pure helpers), rather than shaving
lines.

Three files were brought under it in the 2026-09-15 audit remediation, and are
the models to follow:

| File | Was | Now | How |
| --- | --- | --- | --- |
| `lib/core/i18n/strings.dart` | 3530 | 272 | one file per language under `data/` |
| `lib/pages/sftp_page.dart` | 1182 | 630 | split into `lib/pages/sftp/` |
| `lib/pages/settings_page.dart` | 1044 | 371 | split into `lib/pages/settings/` |

The same treatment was applied to `container_shell_page.dart` (into
`lib/pages/containers/`) and `host_console_page.dart` (into `lib/pages/console/`).

## The icon and the mark

`assets/icon/*.svg` is the source of truth for the app icon; the PNGs under
`android/app/src/main/res/mipmap-*` are generated by `tool/generate_icons.sh` and
must never be hand-edited — a change made only to a PNG is invisible to the next
person who edits the artwork and regenerates, and silently reverts.

The same mark is drawn in-app by `lib/widgets/brand_mark.dart` so it can take its
colours from the theme (the launcher's sage green is unreadable on a light
surface, and a bitmap cannot follow the theme). Two copies of one drawing drift,
so `test/brand_mark_test.dart` reads the SVG and asserts the widget's coordinates
match it: change one and the test fails until both agree.

## Architecture

Documented in `docs/ARCHITECTURE.md` (layer map, coupling rules) and
`docs/MAINTENANCE.md` (code health, monitoring rules). Follow them rather than
re-deriving the structure.

- Pages → providers → services/database. Widgets stay presentation-only.
- Parsing and protocol behaviour belongs in `lib/services`, never in a page.
- Models stay free of Flutter and service dependencies. Do not put UI strings in
  a model — see `lib/models/file_item.dart`, which currently does and should not.

## Secrets

Credentials live in `flutter_secure_storage` (Android Keystore-backed). The
SQLite row stores only the literal `'secure_storage'` as a placeholder. Anything
that moves a secret out of that store — export, backup, sharing — must be
explicit about it and must not route it through the system clipboard.

Android auto-backup is disabled (`android:allowBackup="false"` plus
`res/xml/data_extraction_rules.xml`). Keystore keys are device-bound and are not
backed up, so a restore that resurrects the database without its keys leaves
every credential undecryptable and the host list unloadable. Do not re-enable
either path.

## Open audit

`docs/AUDIT-2026-09-15.html` lists 54 verified defects with `file:line` and fix
direction, ordered by severity, with the recommended fix order at the end. Check
items off there as they are addressed.

**Real capability beats feature count.** Two modules were deleted on 2026-09-15
rather than repaired — a "local shell" and a "wireless ADB" page that fabricated
plausible output, including a device list naming two devices that did not exist.
Before adding a feature, confirm it can actually work; a plausible-looking fake
entry is worse than an absent one.
