编辑凭据时占位符是真实文本，输入会拼接并覆盖原密钥

add_credential_page.dart:52add_credential_page.dart:130add_credential_page.dart:299
问题

P1fail-1

free -m 在非英文 locale 下解析失败，内存永远显示 0%

monitoring_service.dart:118monitoring_service.dart:54host_console_page.dart:148
问题
parseFree 用 line.startsWith('Mem:') 匹配，而 free 是 gettext 本地化的——中文环境下输出的是 内存：（全角冒号）。全项目没有任何地方强制 LC_ALL=C。已在实机验证：LC_ALL=zh_CN.UTF-8 free -m 的行首是 内存：，startsWith('Mem:') 为 false。
后果
中文服务器上 CPU（走 /proc/stat，不受影响）正常，但内存恒为 0.0%、折线图平在 0；而 catch (_) {} 吞掉一切，用户无从得知数据是假的。对中文用户而言监控主功能直接失效。parseTop 的 line.contains('Mem') && ...('total') 同理。
修复
命令改成 LC_ALL=C free -m，或按列位置解析而不是匹配本地化标签。
P1fail-2

parseSystemctl 丢弃全部 failed 单元，「失败」筛选与计数形同虚设

monitoring_service.dart:206systemd_page.dart:29systemd_page.dart:119

P1fail-7

首页探测是自触发的无限循环，App 全生命周期持续重连

home_page.dart:153home_page.dart:38providers.dart:178home_page.dart:63
问题
三个条件叠成闭环：data: builder 每次重建都调 _scheduleStatusProbe；postFrameCallback 在 await _probeHosts 之前就把 _probeScheduled 清掉；setOnline 每次 map 都造新 List 实例，AsyncData 相等性永远为 false → 必通知 → 又重建。两个守卫都拦不住（_probeScheduled 在探测前清、_isProbing 在下一帧到来前清）。已用项目实际的 riverpod 实测：连续三次内容相同的 setOnline 产生三次独立通知。
后果
只要存了 ≥1 台主机，App 就在后台无限循环地对每台主机做完整 TCP + 认证 + 分配登录 shell，每台 ≤4 秒。抽屉用 popUntil(route.isFirst)，HomePage 永驻路由栈底，切到设置页也照跑。持续耗电耗流量，服务器上每秒一条新登录记录，触发 fail2ban 封 IP 是现实风险。
修复
加 _lastProbeAt 节流（或仅在主机 id 集合变化时重探），并让 setOnline 在值未变时直接 return。
P1leak-1

连接过程中离开页面，会在服务器上留下无人关闭的已认证会话

ssh_service.dart:139ssh_service.dart:235host_console_page.dart:215task_manager_page.dart:50systemd_page.dart:46container_shell_page.dart:44
问题
connect() 在每个 await 之后才赋值 _client / _session，而 dispose() 里四个 ?. 调用在那一刻全为 null → 空操作。续体随后把它们建起来，_setState(connected) 还无条件执行。_disposed 只抑制输出流，不阻止连接继续。
后果
在连接窗口（TCP + 握手，300ms–2s，公网更长）内返回，页面没了但服务器上多一个已认证会话和一个登录 shell，永远无人关闭。重复约 10 次（MaxSessions 默认值）后 sshd 开始拒绝新通道——App 的连接、控制台、进程、systemd、容器全部开始报错，服务器上堆着孤儿 bash。四个页面都中招。
修复
在 connect() 的每个 await 之后检查 _disposed，已销毁则清理并退出；dispose() 置一个取消标志，续体据此收敛。

settings_page.dart:213snippet_list_page.dart:111
问题
_showRestoreDialog 的 ctrl、以及 snippet 弹窗的 titleController / commandController 都是每次调用新建且从不 dispose。
后果
每次开关对话框留下一个只靠 GC 回收的 controller，会话内累积；在开启 leak tracker 的测试里会被报出来。
修复
弹窗关闭后 dispose。（注意 snippet_injection_dialog.dart:46 那种「await showDialog 之后 dispose」的写法是正确的，不用改。）

已移除的两个假功能

下面两个模块于 2026-09-15 从代码库中直接删除，连同它们的入口一起。记录在此是为了让审计保持完整——它们不是被修复的，是被移除的；四条相关缺陷也随之消解，而不是得到了修补。

  • 本地终端 · lib/pages/local_shell_page.dart（491 行，已删除）——_executeCommand 是个 switch，按命令名返回硬编码文本：whoami → 'termux'，uname -a → 伪造的内核版本串，ls → 一份常量文件列表。没有任何真实进程执行路径。
  • 无线 ADB · lib/pages/wireless_adb_page.dart（789 行，已删除）——_connectToDevice 只是 await Future.delayed(2 秒) 后无条件写入「已连接」；_generateMockAdbOutput 会编造出 192.168.1.101:5555、.102:5555 两台并不存在的设备，以及带真实时间戳的假 logcat、假的 install ... Success。它伪造的不是命令输出，而是设备列表本身。

随之消解的四条缺陷：这两个模块的伪造本身（原 fail-11、fail-14）、无线 ADB 的开关竞态（原 state-6）、以及本地终端输出的英文硬编码（原 i18n-5）。 删除的只有入口与页面：app_drawer.dart 的两个瓷片、app.dart 的 /shell 与 /adb 两条路由。相关的 i18n key 暂留未删（无害），待后续清理。若之后要做真实的本地终端，Android 上需要 adb 或 Termux 侧的配合——那是一个从零开始的功能，不是恢复这两份文件。

功能缺口

对照仓库里 dev.md 自己的 MVP 规划（那份文档写得很具体），以下是被规划但尚未实现的部分。

  • SFTP 上传与下载 —— MVP 2.0 明确列了这一项，但 sftp_service.dart 只有 list / read / write / delete / rename / mkdir 七个方法，没有上传下载、没有进度、没有可取消的传输队列。
  • 后台传输任务中心 —— PRD 里描述的「带进度圆环、可查看速率与剩余时间、不影响前台操作」的任务中心不存在。task_manager_page.dart 实际是远端 ps aux 进程管理，与传输无关，命名容易让人误会。
  • known_hosts 持久化 —— 这是最该补的一项。host_key_verifier.dart:5 只是个内存 Set，重启即忘。这意味着「主机密钥变了」这个最关键的告警在架构上无法存在，而那正是中间人的唯一信号。修 sec-1 时必须一起做，否则只是把弹窗补上了、检测能力仍然为零。
  • SFTP 多选批量操作 —— PRD 明确要求（长按进多选、底部升起操作栏、批量下载与批量删除）。当前有多选与批量删除，但没有批量下载，且选中状态跨目录不清理（见 state-3）。
  • 断线重连浮层 + buffer 保留 —— PRD 明确要求（切回 App 时若管道已断，叠加半透明遮罩 + 「一键重连」，重连后终端历史必须保留）。终端页有重连入口，但缺少这条体验的完整实现与守卫（见 leak-2）。
  • VNC 远程桌面 —— PRD 第五节的整节内容，目前只是 host_console_page.dart:754 一个 enabled: false 加「即将推出」徽章的占位。这一处是诚实的占位，不算 bug；要决定的是排期还是从 PRD 里降级。
  • 主机分组、标签与搜索 —— 主机一多，首页只有「在线 / 离线」两段平铺列表，没有分组、没有搜索框。
  • SSH 端口转发 / 隧道 —— 常见运维需求，完全缺失。
  • 公钥生成与部署 —— 没有本地生成密钥对、也没有 ssh-copy-id 那类一键部署，用户必须手工处理私钥文本。

已核实、不是 bug

这些是审计过程中看着可疑、但逐条验证后确认没问题的。列出来是为了避免你花时间去「修」它们。

  • app.dart:20 的 firstWhere 带 orElse，不会抛 StateError。全项目也没有任何不带 orElse 的 firstWhere。
  • 悬空的 credential_id 不会崩溃。8 处凭据查找全部用 .where(...).firstOrNull 加本地化的「凭据不存在」提示，HostCard 也对 credentialUsername 做了空值判断。真正的后果是 state-4 和 eng-7，不是崩溃。
  • file_preview_page.dart:71 的 await Future.sync(() => widget.onSave!(...)) 看着像「async 回调挂在 void 签名上没被等待」的经典陷阱。实测确实会等（约 300ms），内层 future 被正确串起来了。
  • systemd_page.dart:116 的 switch 没有 break 不是 bug —— Dart 3 有隐式 break，已用最小用例实测。
  • 恢复备份不会清空已有数据（它只 insert，从不 DELETE）。数据丢失的方向是 data-1，不是覆写。
  • snippet_injection_dialog.dart:46 在 await showDialog 之后 dispose controller / focus node 的写法是正确的，不需要改成别的模式。
  • TerminalController 没有显式 dispose 不会真泄漏（notifyListeners 只由指针/选区输入驱动，它与监听闭包一起变得不可达）。
  • dartssh2 传给回调的确实是 MD5 摘要（MD5Digest().process(hostkey)），所以 formatMd5 的标注正确，不是标错算法。
  • resource_chart.dart 里 spot.x == 19 判断的分支会正常触发 —— fl_chart 的 tick 迭代在收尾时会 yield max，所以「0s」标签是渲染出来的。（我一开始怀疑这条，读了 fl_chart 源码后确认不成立。）
  • 命令注入当前不可达：systemd 单元名与容器名都有字符集限制，kill -9 $pid 的 pid 已解析为 int。不过 systemctl $action $unit 这类不加引号的拼接仍值得加固。
  • flutter analyze 全绿（0 issues）；dist/SHA256SUMS.txt 三个 APK 校验通过；minSdk 24 / targetSdk 36 与 Flutter 3.44 的默认值一致；key.properties 与 .jks 权限均为 600；README 里的版本与包名描述属实。

建议的修复顺序

按「影响 ÷ 改动量」排序。前三条都是一行到几行的改动，但挡住了最严重的后果。

  1. data-1 备份恢复的键名 —— 一个词的改动，挽回永久性数据丢失，而且是用户会真正踩到的路径。
  2. fail-1 + fail-2 free 的 locale 与 systemd 的 ● —— 各一行，直接决定「内存监控」与「服务管理」两个主功能是否可用。
  3. fail-7 首页探测的无限循环 —— 加一个时间戳节流 + setOnline 去重，止住后台持续重连与 fail2ban 风险。
  4. sec-1 + known_hosts 持久化 —— 补上回调只是第一步；把接受过的主机密钥落盘，才能真正检测「密钥变了」。
  5. leak-1 / leak-2 / leak-3 —— 根因都在 SshConnection.connect() 一处：每个 await 之后检查 _disposed。改一个类，修好六个页面。
  6. sec-2 + sec-3 —— 导出改走 SAF 写文件；manifest 加 allowBackup="false" 并给凭据读取失败补降级路径。
  7. data-2 + data-3 —— 凭据编辑表单的占位符与认证方式切换，会损毁密钥，属于必修。
  8. fail-4 / fail-5 / fail-6 —— 让 executeCommand 返回退出码，一次改动同时修掉 systemd、进程管理与容器三处的「假成功」。
  9. fail-8 / fail-9 / fail-10 —— 四个设置项接线或移除；语言在启动时生效；补三条 i18n key。
  10. eng-1 先给四个解析器写单测 —— 做完这一步，P1 里的三条 parser 缺陷以后不会复发。
  11. 其余 P2 / P3 按各自模块的改动窗口顺带处理。
